# Example: Keycloak documentation

A reference configuration that publishes the Keycloak documentation from a fork. It is the only example that depends on Keycloak's AsciiDoc output (link adapter `keycloak_asciidoc`) and is not active in this repository. Repository names and the Pages origin belong to the original deployment (`devrimcode/...`) and must be replaced.

## Files

| File | Purpose |
|---|---|
| `publisher.yml` | The configuration. |
| `publisher.smoke.yml` | Dry-run configuration for acceptance checks (`example.invalid` origin, never published). |
| `source-repository/` | The notifier workflow for the fork, generated by `generate-source-notifier`. |

## Use it as a project

```sh
cp -r examples/keycloak projects/keycloak
```

Then edit `projects/keycloak/publisher.yml`: `publisher.clone_url` and `project.repository_url` (your Publisher repository), `site.base_url`, `site.canonical_base_url` and `site.base_path` (your Pages address), and the source fork (`sources[].vcs.clone_url`, `authoring_targets[]`, `triggers.repository_dispatch.source_repository`) if it is not `devrimcode/keycloak`. Check the result and generate both workflows inside the Git checkout:

```sh
python -m publisher_engine.cli validate-config --config projects/keycloak/publisher.yml
python -m publisher_engine.cli generate-workflow --config projects/keycloak/publisher.yml --replace-existing
python -m publisher_engine.cli generate-source-notifier --config projects/keycloak/publisher.yml --replace-existing
```

Commit the workflow to the default branch, set **Settings > Pages > Source** to **GitHub Actions**, install the generated notifier in the fork and add the secret `PUBLISHER_DISPATCH_TOKEN` there, see [docs/SOURCE-TO-PUBLISHER-AUTOMATION.md](../../docs/SOURCE-TO-PUBLISHER-AUTOMATION.md). The tests check that the committed notifier in this directory matches the generated one.

## Repository roles in the example

- Publisher and GitHub Pages workflow: `devrimcode/documentation-publisher`.
- Build source: `devrimcode/keycloak`, branch `main`. The notifier triggers a rebuild on every push.
- Source-link provenance: `keycloak/keycloak` stays `sources[].vcs.web_url`, because Keycloak's AsciiDoc header generates its links with that canonical URL. The physical clone (`sources[].vcs.clone_url`) is the fork. The adapter validates the original header URL and then maps the edit path to the fork.
- Edit links point to the fork, issue links stay at `keycloak/keycloak/issues`, and navigation links are inherited unchanged from Keycloak's generated documentation (`links.navigation.mode: inherit`), so they keep pointing to `www.keycloak.org`.
- Event type `keycloak-documentation-updated`; the commit is passed through `PUBLISHER_KEYCLOAK_SOURCE_SHA`.

## Build environment

The generated workflow configures Temurin JDK 25 through a pinned `actions/setup-java` action, matching Keycloak's documentation CI. The build step receives the Maven Resolver arguments used by Keycloak's documentation workflow:

`-B -nsu -Daether.connector.http.connectionMaxTtl=25 -Daether.connector.http.retryHandler.count=5 -Daether.connector.http.retryHandler.serviceUnavailable=429,502,503,504`

The Maven command itself is the build task in `publisher.yml`.
