# Projects

A project directory describes one published documentation project: which repositories to read, how to build them, where links should point and where the result is published. The engine in `publisher_engine/` does not depend on any project. This repository ships no project yet; create your own, or start from an example.

```
projects/<name>/
  publisher.yml                  required: the configuration
  README.md                      optional: notes specific to the project
  publisher.smoke.yml            optional: dry-run configuration for acceptance checks
  source-repository/             generated by `generate-source-notifier`
```

- Create one with `documentation-publisher init-config --output projects/<name>/publisher.yml`, see [docs/ADDING-A-PROJECT.md](../docs/ADDING-A-PROJECT.md).
- The workflow of this repository, `.github/workflows/documentation-publisher.yml`, is generated from one project's configuration. Until you generate it, nothing is built or deployed.
- Examples: [`examples/mkdocs`](../examples/mkdocs/README.md) (MkDocs) and [`examples/keycloak`](../examples/keycloak/README.md) (Keycloak documentation).
- Not to be confused with `--profile`: that option layers named configuration overlays such as `staging` or `production`, see [docs/CONFIGURATION.md](../docs/CONFIGURATION.md).
